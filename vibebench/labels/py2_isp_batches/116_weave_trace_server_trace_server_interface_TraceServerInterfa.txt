     1555              raise ValueError("Missing chunks")

     1558              # writes of the same digest AND the effective `FILE_CHUNK_SIZE`

     1560              # of any previous write. In that case, you have something like tthe following:
     1561              # Consider a file of size 500 bytes.
     1562              # Insert Batch 1 (chunk_size=100): C0(0-99), C1(100-199), C2(200-299), C3(300-399), C4(400-499)
     1563              # Insert Batch 2 (chunk_size=50): C0(0-49), C1(50-99), C2(100-149), C3(150-199), C4(200-249), C5(250-299), C6(300-349), C7(350-399), C8(400-449), C9(450-499)
     1564              # Insert Batch 3 (chunk_size=200): C0(0-199), C1(200-399), C2(400-499)
     1565              #
     1566              # When Clickhouse runs it's merge operation, it keeps the last inserted rows according to the index (project, digest, chunk_index).
     1567              # Similarly, the inner select statement in the query above (partitioned and keep row 1) does the same thing.
     1568              #
     1569              # As a result, the resulting query gives you all the chunks from batch 3, then any "extra" chunks from previous batches.
     1570              # |--------- Insert Batch 3 --------| |-------------------------- Extra Chunks from Batch 2 -----------------------------------|
     1571              # C0(0-199), C1(200-399), C2(400-499), C3(150-199), C4(200-249), C5(250-299), C6(300-349), C7(350-399), C8(400-449), C9(450-499)

     1579              # However, with bucket storage, we don't chunk at all - storing the data effectively as a single chunk.

     1582              # reach a situation that matches the general case above.
