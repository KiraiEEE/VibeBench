\begin{Arabic}
\noindent شهدت السنوات الأخيرة تطورًا لافتًا في عملاء البرمجة الذاتيين، إذ باتت الشفرة التي
ينتجونها تُقدَّم فعليًا إلى مشاريع برمجية حقيقية. غير أنّ معايير التقييم المعتمدة حاليًا تكاد تقتصر
على قياس الصحة الوظيفية للشفرة، تاركةً جودة العمارة البرمجية دون توصيف دقيق. تدرس هذه الأطروحة مدى
التزام الشفرة الصادرة عن ثلاثة من أبرز هذه العملاء، وهي Claude Code وGitHub Copilot وOpenAI Codex،
بمبادئ التصميم الخمسة SOLID، اعتمادًا على 4245 طلب دمج (pull request) بلغة جافا موزّعة على 1010
مستودعات. ويشمل الفحص الطلبات المدمجة والمرفوضة والمفتوحة على حدّ سواء، إذ إنّ الاقتصار على الشفرة
المدمجة يقيس ما قبله المراجعون لا ما أنتجه العميل.

ولتحقيق ذلك، اعتُمد لكل مبدأ مؤشرٌ بنيويٌّ حتميٌّ (deterministic)، وجرى قياس صدقه لا افتراضه: إذ
خضعت 1400 حالة، مئة مُعلَّمة ومئة غير مُعلَّمة لكل مبدأ، مع جولة تحقّقٍ ثانيةٍ مستقلّة لمبدأَين
منها، لحكم قراءةٍ مستقلٍّ يسجّل سبب كل حكم. وتراوحت الدقّة بين 0.330 و0.890، أمّا نسبة الاسترجاع
بعد ترجيح الطبقات فقد تراوحت بين 0.733 و1.000 في ثلاثة مبادئ، ممّا يجعل نسبها حدًّا أعلى، بينما
انخفضت إلى 0.352 و0.552 في المبدأَين اللذين لا يرصدان سوى المخالفات المعلنة بنيويًّا. وتكشف النتائج
أنّ الخلل يتركّز داخل الوحدة البرمجية الواحدة: فمن بين نحو 4100 مخالفة لمبدأ المسؤولية الواحدة
موجودة أصلًا في الشفرة التي عدّلها العملاء، لم تُدخِل هذه العملاء مخالفةً جديدة إلّا في اثنين إلى
أربعة بالمئة من طلباتها. كما تبيّن أنّ الطلبات المدمجة والمرفوضة لا تكاد تختلف بنيويًّا، ممّا يشير
إلى أنّ المراجعة البشرية لا تنتقي على أساس هذه الخصائص.

\flagicon{flag_usa}\quad{\large\bfseries\color{issatblue} Abstract}
\end{center}
\vspace{2pt}
\noindent Autonomous coding agents now author code submitted to real software projects, yet
existing benchmarks measure functional correctness almost exclusively, leaving architectural
quality uncharacterised. This thesis measures whether code from three agents, Claude Code, GitHub
Copilot and OpenAI Codex, adheres to the five \textsc{solid} principles, across \textbf{4{,}245
Java pull requests in 1{,}010 repositories}. The corpus covers requests that were merged, rejected
and still open, because a merged-only corpus measures what maintainers accepted rather than what
agents produced.

Each principle is operationalised as a deterministic structural proxy, and construct validity is
measured rather than assumed: \textbf{1{,}400 entities}, 100 flagged and 100 unflagged per
principle plus a 200-entity holdout for two of them, were read and labelled by an independent judge
that recorded its reason for every verdict. Precision ranges from 0.330 to 0.890. Stratum-weighted
recall runs from 0.733 to 1.000 for three principles, whose reported rates are therefore upper
bounds, and falls to 0.352 and 0.552 for the two that detect only structurally declared violations.
The labels identify restrictions that raise two detectors to 0.786 and 1.000, the second of which
held exactly on the holdout.

Risk is concentrated \emph{inside} single units. Of roughly 4{,}100 single-responsibility
violations already present in the code these agents touched, the agents introduced a violation in
two to four per cent of their pull requests; relation-level principles such as Liskov Substitution
show 681 violations present against 16 introduced, because a fault spanning two units is rarely
authored by one change. Merged and rejected pull requests are structurally indistinguishable once
reconstruction method is held constant, which indicates that human review does not select on these
properties.

\vspace{4pt}
\noindent\textbf{Keywords:} coding agents, SOLID principles, software architecture, static
analysis, empirical software engineering, construct validity.

\begin{french}
\noindent Les agents de codage autonomes produisent du code soumis \`a de vrais projets
logiciels, mais les r\'ef\'erentiels existants mesurent presque exclusivement la correction
fonctionnelle, laissant la qualit\'e architecturale non caract\'eris\'ee. Cette th\`ese mesure si
le code de trois agents, Claude Code, GitHub Copilot et OpenAI Codex, respecte les cinq principes
\textsc{solid}, sur \textbf{4~245 \emph{pull requests} Java r\'eparties sur 1~010 d\'ep\^ots}. Le
corpus couvre les demandes fusionn\'ees, rejet\'ees et encore ouvertes, car un corpus limit\'e au
code fusionn\'e mesure ce que les mainteneurs ont accept\'e plut\^ot que ce que les agents ont
produit.

Chaque principe est op\'erationnalis\'e par un indicateur structurel d\'eterministe, et la
validit\'e de construit est mesur\'ee plut\^ot que suppos\'ee~: \textbf{1~400 entit\'es}, 100
signal\'ees et 100 non signal\'ees par principe, plus un \'echantillon de contr\^ole de 200 pour
deux d'entre eux, ont \'et\'e lues et annot\'ees par un juge ind\'ependant consignant la raison de
chaque verdict. La pr\'ecision varie de 0,330 \`a 0,890. Apr\`es pond\'eration des strates, le
rappel va de 0,733 \`a 1,000 pour trois principes, dont les taux constituent donc une borne
sup\'erieure, mais tombe \`a 0,352 et 0,552 pour les deux qui ne d\'etectent que les violations
structurellement d\'eclar\'ees.

Le risque se concentre \emph{\`a l'int\'erieur} des unit\'es. Sur environ 4~100 violations du
principe de responsabilit\'e unique d\'ej\`a pr\'esentes dans le code touch\'e, les agents n'en
introduisent que dans deux \`a quatre pour cent de leurs demandes~; pour la substitution de Liskov,
681 violations sont pr\'esentes contre 16 introduites, un d\'efaut reliant deux unit\'es \'etant
rarement produit par un seul changement. Les demandes fusionn\'ees et rejet\'ees sont
structurellement indiscernables, ce qui indique que la revue humaine ne s\'electionne pas sur ces
propri\'et\'es.

\end{french}
