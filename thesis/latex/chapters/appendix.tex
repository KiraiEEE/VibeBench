\chapter{Pipeline Run Order and Reproducibility}
\label{app:pipeline}

This appendix lists the exact stage order used to reproduce the results reported in
Chapter~\ref{ch:results}. Every stage is resumable and checkpointed; re-running a stage after a
threshold change requires deleting that stage's output parquet first, since resumption otherwise
keeps previously-computed rows.

\footnotesize
\begin{verbatim}
curate.py --lang java      -> gold set        6,956 PRs / 1,010 repos,
                                              balanced on agent x outcome
clone_and_extract.py       -> file lists      GitHub API where local
                                              history is insufficient
mvn -o package (sidecar)   -> facts jar       JavaParser + SymbolSolver
run_java.py                -> five parquets   one parsed tree feeds all
                                              five principles; 4,245 ok
   (thresholds calibrated from corpus percentiles, then parquets
    deleted and the pass re-run, so no flag predates its threshold)
report_java.py             -> per-agent and per-outcome summaries
make_java_labeling_sample.py  -> 100 flagged + 100 unflagged per principle
extract_java_label_batches.py -> the source shown to the judge
audit_label_batches.py     -> GATE: every row must trace to that source,
                              and no batch may leak the detector's verdict
score_labels.py            -> precision and recall per principle,
                              per agent, per outcome
run_crosscheck_java.py     -> CK, PMD, DesigniteJava over the same trees
verify_v2_java.py          -> whole-corpus invariants; exits non-zero
                              on any failure
\end{verbatim}
\normalsize

A single combined delta pass (\texttt{run\_java.py}) computes all five principles from one parsed
tree, since parsing costs 10--20 seconds per tree and five separate harnesses would each pay that
cost independently. Extracted facts are cached by the content hash of the tree, so re-running
cannot silently change an input.

\section*{Software and Data Availability}

The corpus is derived from the public AIDev dataset \citep{li2025aidev}. The analysis pipeline,
configuration, and result tables are version-controlled; source code is available from the author
upon request. No proprietary code, personal data, or human-participant data was collected or is
distributed as part of this work.

\section*{Configuration Discipline}

All thresholds, file paths, and policy knobs (agent PR caps, star and license floors, rubric
cut-points, suppressor toggles) live in a single, heavily-commented configuration module per
language, so that a threshold change is a one-line, auditable edit rather than a scattered one.
Every pure evaluator module carries an inline self-check, a small hand-built example with a
known answer, run whenever that module changes, which is the closest analogue this pipeline has
to a unit-test suite, chosen deliberately over a conventional test framework so that the check
travels with the module it verifies.
